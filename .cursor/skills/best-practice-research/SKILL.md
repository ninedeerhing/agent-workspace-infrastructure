# 最佳实践调研 (Best-Practice Research)
当任务依赖于当前外部最佳实践、版本感知指导、标准、官方推荐或上游行为时使用此技能。这是一个工作流封装（workflow wrapper）：它路由证据收集和综合；它不是新的调研权威，也不替代 `researcher`。
## 用途 (Purpose)
生成一份可引用的、可复用的最佳实践答案或交接物，将当前外部证据与仓库本地事实及依赖选择决策分离。作为规划前的调研入口，本技能收集官方/上游证据后交给 `$ralplan` 或调用方作为规划输入。不要将本技能呈现为最终架构组件或带验证门的调研循环。
## 触发条件 (Activate When)
- 用户询问最佳实践、推荐方法、当前指导、官方推荐、标准或版本感知的外部行为。
- `$ralplan`、`$deep-interview`、`$team` 或其他工作流在进行规划或执行前需要当前外部证据。
- 任务涉及已选定的技术，需要权威使用指导、迁移说明、API 行为、生命周期规则或当前安全指导。
## 不触发条件 (Do Not Activate When)
- 答案完全在仓库本地范围内；使用 `explore` 获取代码库事实。
- 主要问题是是否采用、替换、升级或比较依赖项；使用 `dependency-expert`。
- 用户只需要基于已确定的规格进行实现；使用 `executor`、`$ralph-loop` 或 `$team`。
- 任务可以通过稳定的本地项目约定回答，无需当前外部查询。
## 专家路由 (Specialist Routing)
1. 对于已有代码（brownfield）事实，优先使用 `explore`：当前代码使用情况、本地约束、版本、配置和集成点。
2. 对于已选定技术的官方/上游文档、发布说明、标准、迁移指南、源码示例和当前最佳实践证据，使用 `researcher`。
3. 仅在涉及采用/升级/替换/比较决策时使用 `dependency-expert`。
4. 带着明确的证据、不确定性和实现交接约束返回给调用方。
## 证据质量规则 (Source-Quality Rules)
- 优先使用官方文档、上游源码、发布说明、变更日志、标准和维护者指导。
- 对实质性声明包含来源 URL。
- 对当前最佳实践声明标注日期/版本上下文。
- 将第三方摘要标注为补充性（supplemental）；不在官方/上游来源之前使用。
- 标记过时、冲突、无文档或版本不匹配的证据。
- 不过度获取：收集足以支持决策的最小证据集。
## 工作流 (Workflow)
1. 分类问题：概念性最佳实践、实现指导、迁移/版本指导、标准/合规指导、或混合本地+外部指导。
2. 当本地使用情况或约束影响答案时，使用 `explore` 收集仓库本地事实。
3. 当当前或版本感知的实践影响正确性时，使用 `researcher` 收集外部证据。
4. 综合简洁的答案，包含证据质量、版本/日期上下文、注意事项以及实现或规划交接。
5. 当答案足够支撑调用方决策时停止；否则报告确切的阻塞点或所需的专家交接。
## 输出契约 (Output Contract)
```md
## 最佳实践调研: <question>
### 直接建议 (Direct Recommendation)
<可操作的指导或决策支持>
### 使用的证据 (Evidence Used)
- 官方/上游: <source URL> — <所确立的内容>
- 补充性（如有）: <source URL> — <为什么是次要来源>
### 版本/日期上下文 (Version / Date Context)
<版本、日期、发布渠道或未知项>
### 仓库本地上下文 (Repo-Local Context)
<来自 explore 的事实，或 "不需要">
### 边界/非目标 (Boundaries / Non-goals)
<本调研不做决定的内容>
### 交接 (Handoff)
<规划/执行/测试的影响>
```
## 停止规则 (Stop Rules)
- 在有来源支撑的建议可被调用方复用后停止。
- 如果任务变为依赖比较、广泛架构或实现时，停止并向上路由。
- 当剩余工作仅能润色措辞而不会改变建议时，不要继续调研。
