# Ultragoal — 持久多目标执行
## 定位
管理多个长期目标的持久化执行系统。使用仓库原生工件（brief/goals/ledger）在会话间保持状态，支持聚合模式和单故事模式。
## 触发条件
- 项目包含多个目标或里程碑
- 需要跨会话跟踪进度
- 需要持久化的任务状态
- 长期运行的项目
## 核心工件
### brief.md（项目摘要）
项目级别的元信息：
```markdown
# Project Brief
- 项目名称
- 一句话描述
- 当前阶段
- 活跃目标列表
- 最近更新日期
```
### goals/（目标目录）
每个目标一个文件：
```markdown
# Goal: [目标名称]
- 状态: [active/blocked/completed]
- 优先级: [P0/P1/P2]
- 创建日期
- 成功标准
- 当前进度
- 阻塞项
```
### ledger.md（交易日志）
不可变的操作日志：
```markdown
## [时间戳] [操作类型]
- 操作: [描述]
- 影响目标: [目标ID]
- 结果: [成功/失败/部分]
- 证据: [验证结果]
```
## 两种执行模式
### 聚合模式（Aggregate）
- 每次会话处理一个目标
- 深入完成该目标的当前任务
- 适合有明确依赖顺序的目标
### 单故事模式（Per-Story）
- 每次会话处理一个独立的用户故事
- 快速切换目标
- 适合独立的小任务
## 会话流程
1. **启动**：读取 brief.md，了解项目状态
2. **选择**：选择当前要推进的目标
3. **执行**：按模式执行任务
4. **记录**：更新 goals/ 和 ledger.md
5. **交接**：更新 brief.md，标记下一步
## 反模式 / 红牌
| 反模式 | 说明 |
|--------|------|
| 不更新工件 | 红牌。每次操作必须更新对应文件 |
| 目标数量失控 | 黄牌。活跃目标不超过 5 个 |
| ledger 不完整 | 红牌。所有操作必须有日志 |
| 跳过启动读取 | 红牌。每次会话必须读 brief.md |
