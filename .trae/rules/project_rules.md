# TRAE Workspace — Trae IDE 项目规则

本文件是专门为 Trae IDE 配置的项目级规则。当在 Trae IDE 中打开此工作区时，这些规则将被自动加载。

---

## 项目语言偏好

- **对话语言**：中文（简体）。
- **代码注释语言**：中文（简体），函数级注释。
- **文档语言**：中文（简体）。
- **Commit Message 语言**：英文（遵循 Conventional Commits 格式）。

---

## 系统环境

- **操作系统**：Windows
- **Shell**：PowerShell
- **路径分隔符**：反斜杠 `\`（Windows 风格）
- **文件编码**：UTF-8

---

## 核心工作流规则

### 任务执行

1. 接到任务后，先明确目标、范围、验收标准，再动手。
2. 对于多步骤任务，先在内部规划步骤，再逐步执行。
3. 每一步完成后进行最小验证，不等到最后才检查。
4. 遇到阻塞时，尝试替代方案；真正无法推进时才询问。
5. 自主执行低风险、可逆操作；不可逆操作（删除、生产变更）需确认。

### 代码修改

1. 只修改与当前任务直接相关的文件，不做顺手重构。
2. 修改前先理解周围代码的上下文和约定。
3. 遵循项目中已有的代码风格、库选择和命名约定。
4. 不添加未在任务需求中要求的依赖。
5. 每次修改后运行 lint 和 typecheck 验证。

### 验证要求

1. 声明任务完成前必须提供验证证据。
2. 验证优先级：针对性测试 → typecheck/lint → 构建 → 冒烟测试。
3. 无法运行验证时，必须说明原因并使用次优证据。
4. 不跳过验证步骤。

## 代码生成要求

### 注释规范

1. **函数级注释**：每个函数必须有中文注释，说明：
   - 函数用途
   - 关键参数含义
   - 返回值说明（如有）
   - 副作用或注意事项（如有）

2. **不添加多余注释**：
   - 不在每行代码都加注释。
   - 不注释自明代码（如 `i++ // 自增 i`）。
   - 不保留被注释掉的旧代码。

3. **注释风格示例**：

```javascript
/**
 * 计算两个日期之间的工作日天数
 * @param {Date} startDate - 起始日期
 * @param {Date} endDate - 结束日期
 * @returns {number} 工作日天数（不含周末）
 */
function getWorkingDays(startDate, endDate) {
  // 实现逻辑
}
```

### 代码风格

1. 遵循项目已有的代码风格约定。
2. 使用有意义的变量和函数名，避免缩写（领域通用缩写除外）。
3. 函数保持短小（50 行以内），文件保持聚焦（800 行以内）。
4. 避免深度嵌套（不超过 4 层）。
5. 错误必须被处理，禁止空 catch 块。

### 安全要求

1. 绝不生成包含硬编码密钥、密码或令牌的代码。
2. 绝不生成包含 SQL 拼接的数据库查询代码（使用参数化查询）。
3. 用户输入必须经过验证后再使用。
4. 敏感操作的代码必须有适当的权限检查。

## 文件组织偏好

- 按功能/领域组织文件，而非按文件类型。
- 小文件优于大文件（200-400 行理想范围）。
- 相关的测试文件与源文件放在一起或对应的测试目录中。
