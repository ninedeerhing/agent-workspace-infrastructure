# Dispatching Parallel Agents — 分派并行代理

## 定位

当存在多个完全独立的、无共享状态的任务时，将它们并行分派给多个子代理同时执行，最大化效率。

## 触发条件

- 有 2 个或更多独立任务
- 任务之间无共享状态（不修改相同的文件、不依赖彼此的输出）
- 每个任务有明确的完成标准
- 环境支持同时运行多个子代理

## 适用性判断

**可以使用并行分派**：
- 多个独立的 bug 修复
- 不同模块的独立功能实现
- 独立的文档编写任务
- 独立的代码审查任务

**不能使用并行分派**：
- 任务之间有数据依赖
- 任务修改相同的文件
- 任务有顺序依赖（B 必须在 A 之后）
- 共享数据库或全局状态

## 执行流程

### 第 1 步：任务拆分

- 将总任务拆分为独立的子任务
- 确认每个子任务之间无共享状态
- 为每个子任务定义清晰的输入和完成标准

### 第 2 步：同时分派

- 一次性创建所有子代理
- 每个子代理获得独立、完整的指令
- 确保子代理不互相引用或依赖

### 第 3 步：收集结果

- 等待所有子代理完成
- 收集各自的输出和状态报告
- 每个子代理使用四状态协议：DONE / DONE_WITH_CONCERNS / BLOCKED / NEEDS_CONTEXT

### 第 4 步：整合

- 整合所有子代理的输出
- 检查是否有跨任务的不一致
- 执行一次整体验证

## 反模式 / 红牌

| 反模式 | 说明 |
|--------|------|
| 有依赖的任务并行化 | 红牌。有依赖必须串行 |
| 修改相同文件 | 红牌。会导致冲突 |
| 不检查共享状态 | 红牌。必须确认无共享状态 |
| 子代理数量过多 | 黄牌。一般不超过 5 个 |
| 任务粒度不均 | 黄牌。尽量拆分为相似工作量 |
