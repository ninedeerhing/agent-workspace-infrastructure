# Deepinit — 层次化项目指令生成
## 定位
扫描项目结构，分析技术栈和关键模块，生成从根目录到各子目录的层次化 AGENTS.md 文件体系。每个 AGENTS.md 文件为 AI 代理描述该目录的用途、关键文件、依赖关系和特殊指令。
## 触发条件
- 用户提到 `deepinit`、`generate AGENTS.md`、`init project structure`
- 新项目初始化，需要 AI 可读的项目文档
- 现有项目缺少 AGENTS.md，需要批量生成
- 项目结构变化后需要更新 AGENTS.md
## 层次化标记系统
每个 AGENTS.md（除根目录外）包含父引用标记：
```markdown
<!-- Parent: ../AGENTS.md -->
```
形成可导航的层次结构：
```
/AGENTS.md                          ← 根（无父引用标记）
├── src/AGENTS.md                   ← <!-- Parent: ../AGENTS.md -->
│   ├── src/components/AGENTS.md    ← <!-- Parent: ../AGENTS.md -->
│   └── src/utils/AGENTS.md         ← <!-- Parent: ../AGENTS.md -->
└── docs/AGENTS.md                  ← <!-- Parent: ../AGENTS.md -->
```
## AGENTS.md 模板
```markdown
<!-- Parent: {相对父路径}/AGENTS.md -->
<!-- Generated: {时间戳} | Updated: {时间戳} -->
# {目录名称}
## 用途
{一段话描述本目录包含什么及其角色}
## 关键文件
| 文件 | 描述 |
|------|------|
| `file.ts` | 简要用途描述 |
## 子目录
| 目录 | 用途 |
|------|------|
| `subdir/` | 包含什么（参见 `subdir/AGENTS.md`） |
## 给 AI 代理
### 在此目录工作
{AI 代理修改此处文件时的特殊指令}
### 测试要求
{如何测试此目录中的更改}
### 常见模式
{此处使用的代码模式或约定}
## 依赖关系
### 内部
{引用代码库中依赖的其他部分}
### 外部
{使用的主要外部包/库}
<!-- MANUAL: 在此行以下添加的手动注释在重新生成时保留 -->
```
## 执行流程
### 第 1 步：扫描项目结构
- 递归列出所有目录
- 排除：node_modules、.git、dist、build、__pycache__、.venv、coverage、.next、.nuxt
- 记录目录树拓扑
### 第 2 步：分析技术栈
- 读取 package.json / pyproject.toml / Cargo.toml 等构建文件
- 识别语言、框架、测试工具
- 分析目录命名约定和组织模式
### 第 3 步：识别关键模块
- 标记包含源代码的核心目录
- 识别测试目录和文档目录
- 标注配置文件和入口点
### 第 4 步：生成入口指令（根 AGENTS.md）
- 项目总览：名称、用途、技术栈
- 关键文件列表和描述
- 子目录索引（带链接）
- AI 代理的全局指令
- 外部依赖列表
### 第 5 步：生成子目录指令
- 按层级从上到下生成
- 父目录先生成，确保子目录的父引用有效
- 同级目录可并行生成
对每个目录：
1. 读取目录中的所有文件
2. 分析用途和关系
3. 生成 AGENTS.md 内容
4. 写入文件并附正确的父引用
### 第 6 步：更新已有 AGENTS.md
当 AGENTS.md 已存在时：
1. 读取现有内容
2. 识别自动生成部分和手动部分（`<!-- MANUAL -->` 以下）
3. 对比：新增文件？删除文件？结构变化？
4. 合并：更新自动生成内容，保留手动注释
### 第 7 步：验证层次结构
| 检查项 | 验证方法 | 修正动作 |
|--------|---------|---------|
| 父引用可解析 | 读取每个 AGENTS.md，检查父路径存在 | 修复路径或删除孤本 |
| 无孤立 AGENTS.md | 比较 AGENTS.md 位置与目录结构 | 删除孤立文件 |
| 完整性 | 列出所有目录，检查是否有 AGENTS.md | 生成缺失文件 |
| 时间戳最新 | 检查生成日期 | 重新生成过时文件 |
## 空目录处理
| 情况 | 动作 |
|------|------|
| 无文件、无子目录 | 跳过——不创建 AGENTS.md |
| 无文件、有子目录 | 创建最小 AGENTS.md（仅子目录列表） |
| 仅生成文件（.min.js、.map） | 跳过或最小 AGENTS.md |
| 仅配置文件 | 创建描述配置用途的 AGENTS.md |
## 智能代理分派
| 任务 | 代理 |
|------|------|
| 目录映射 | `explore` |
| 文件分析 | `architect` |
| 内容生成 | `writer` |
| AGENTS.md 写入 | `writer` |
## 并行化规则
1. 同级目录：并行处理
2. 不同层级：顺序处理（父优先）
3. 大目录：每个目录分配独立代理
4. 小目录：多个小目录批量放入一个代理
## 质量标准
### 必须包含
- 准确的文件描述
- 正确的父引用
- 子目录链接
- AI 代理指令
### 必须避免
- 通用模板文字
- 错误的文件名
- 断开的父引用
- 遗漏重要文件
## 反模式 / 红牌
| 反模式 | 说明 |
|--------|------|
| 子目录先生成 | 红牌。父目录未生成时子目录父引用断开 |
| 覆盖手动注释 | 红牌。`<!-- MANUAL -->` 以下内容必须保留 |
| 忽略空目录规则 | 黄牌。空目录不应生成 AGENTS.md |
| 父引用路径错误 | 红牌。父引用路径必须可解析 |
| 缺少 AI 代理指令 | 黄牌。每个 AGENTS.md 应包含代理可用指导 |
| 跳过验证 | 红牌。生成后必须验证层次完整性 |
## 成功标准
- 所有有内容的目录都有对应的 AGENTS.md
- 所有父引用路径可解析
- 无孤立的 AGENTS.md 文件残留
- 根 AGENTS.md 包含完整的项目概览
- 手动注释在更新时被保留
- 层次结构可导航（从根可到达任意子目录的 AGENTS.md）
