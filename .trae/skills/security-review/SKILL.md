# Security Review — 安全审查
## 定位
以首席安全官（CSO）视角执行安全审查。基于 OWASP Top 10 进行系统化安全检查，含防误报门控机制。
## 触发条件
- 功能完成，准备发布前
- 涉及认证/授权/支付/数据处理的代码
- 敏感功能变更
- 安全事件响应后
## OWASP Top 10 检查清单
### 1. Broken Access Control（访问控制失效）
- [ ] 每个端点是否验证用户权限？
- [ ] 是否有越权风险（IDOR）？
- [ ] API 是否正确验证 token？
- [ ] 角色权限是否最小化？
### 2. Cryptographic Failures（加密失败）
- [ ] 敏感数据是否加密传输？
- [ ] 密码是否使用安全哈希（bcrypt/argon2）？
- [ ] 密钥是否硬编码？
- [ ] 是否使用过时的加密算法（MD5/SHA1）？
### 3. Injection（注入）
- [ ] SQL 查询是否参数化？
- [ ] 用户输入是否验证和清理？
- [ ] 是否使用了 ORM/安全查询构建器？
- [ ] OS 命令是否避免拼接用户输入？
### 4. Insecure Design（不安全设计）
- [ ] 安全需求是否在设计阶段考虑？
- [ ] 是否有威胁建模？
- [ ] 信任边界是否明确？
### 5. Security Misconfiguration（安全配置错误）
- [ ] 默认密码是否已修改？
- [ ] 错误信息是否暴露内部细节？
- [ ] CORS 配置是否合理？
- [ ] 不必要的 HTTP 方法是否禁用？
### 6. Vulnerable Components（易受攻击组件）
- [ ] 依赖是否有已知漏洞？
- [ ] 依赖版本是否最新？
- [ ] 是否使用了已弃用的库？
### 7. Auth Failures（认证失败）
- [ ] 密码策略是否合理？
- [ ] 登录失败是否有速率限制？
- [ ] 会话管理是否安全？
- [ ] 是否支持 MFA？
### 8. Software and Data Integrity Failures（软件和数据完整性失败）
- [ ] CI/CD 流水线是否安全？
- [ ] 第三方库是否验证完整性？
### 9. Logging and Monitoring Failures（日志和监控失败）
- [ ] 安全事件是否记录？
- [ ] 日志是否包含敏感信息？
- [ ] 异常活动是否有告警？
### 10. SSRF（服务器端请求伪造）
- [ ] 用户控制的 URL 是否验证？
- [ ] 内部服务请求是否受限？
## 防误报门控
安全审查必须遵循"证据优先"原则：
1. **只能是确实存在的漏洞**：不能报告"可能"的安全问题
2. **必须提供代码位置**：指向具体文件和行号
3. **必须提供利用场景**：描述攻击者如何利用该漏洞
4. **分级严格**：
   - **Critical**：可远程利用、数据泄露、权限提升
   - **High**：需要特定条件但仍可被利用
   - **Medium**：防御深度问题
   - **Low**：最佳实践建议
## 反模式 / 红牌
| 反模式 | 说明 |
|--------|------|
| 跳过 OWASP 检查 | 红牌。必须逐项检查 |
| 报告不存在的问题 | 红牌。安全审查必须基于证据 |
| 不提供代码位置 | 红牌。每个问题必须指向具体代码 |
| 忽略误报控制 | 红牌。不能提"可能"的问题 |
| 不检查依赖漏洞 | 黄牌。易受攻击组件是常见入口 |
