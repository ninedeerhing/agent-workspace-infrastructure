# Plan Eng Review — 工程审查
## 定位
以工程经理的视角审查技术方案。强制使用图表暴露隐藏假设，关注可实现性、风险和资源。
## 触发条件
- `ralplan` 完成或有技术方案
- 需要从工程管理角度审查
- 准备开始执行前
## 强制图表要求
必须使用以下至少一种图表暴露隐藏假设：
### 系统架构图
```
[用户] → [API Gateway] → [Service A] → [Database A]
                        → [Service B] → [Database B]
                        → [Cache]
```
### 数据流图
追踪数据从产生到消费的完整路径。
### 序列图
关键交互的时序图，暴露组件间的协议和契约。
### 部署拓扑图
展示服务如何部署、扩展和通信。
## 审查维度
### 可实现性
- 技术上是否可行？
- 依赖的服务和库是否稳定？
- 是否有已知的技术障碍？
### 工作量评估
- 拆解为具体任务后，每个任务需要多少时间？
- 是否有高风险任务？
- 并行化程度如何？
### 风险矩阵
| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|----------|
| ... | 高/中/低 | 高/中/低 | ... |
### 依赖管理
- 外部依赖的 SLA 是什么？
- 内部依赖团队的时间和承诺？
- 是否有单点故障依赖？
## 反模式 / 红牌
| 反模式 | 说明 |
|--------|------|
| 无图表审查 | 红牌。必须用图表暴露假设 |
| 无风险评估 | 红牌。每个方案必须有风险矩阵 |
| 依赖未确认 | 红牌。依赖必须已确认 |
| 乐观估计 | 黄牌。工作量加 50% buffer |
