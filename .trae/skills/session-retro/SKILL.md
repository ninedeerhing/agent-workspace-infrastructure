# Session Retro — 会话复盘与模式提取

## 定位

每次会话结束前的强制复盘技能。不是简单的"做了什么"的总结，而是结构化的经验提取——将本次会话中的新发现、新方法、新错误转化为可复用的知识和技能。

## 触发条件

- 会话即将结束（用户发出明显结束信号）
- 一组任务完成后（≥3 个相关任务）
- 用户明确要求"回顾"、"总结"、"提取模式"
- 在 session-handoff.md 更新之前自动触发

## 复盘流程（4 步）

### 第 1 步：事实回顾

不评价、不总结、不抽象——只回溯原始事实：

1. 阅读 `harness/progress.md` 本次会话的 What's Done 章节
2. 阅读 `harness/workflow-state.json` 的阶段历史
3. 列出本次会话中**所有文件变更**（创建、修改、删除）
4. 列出本次会话中**所有通过的检查**（类型、lint、测试、审查）
5. 列出本次会话中**所有失败的检查**（原因和修复方式）

输出：`retro-facts`（纯列表，不带解释）。

### 第 2 步：模式提取

从事实中提取 3 类可复用模式：

| 模式类型 | 提取标准 | 目标 |
|----------|----------|------|
| **可复用方法** | 本次使用的方法在未来类似任务中可直接复用 | 写入 writing-skills 或 skillify |
| **经验教训** | 本次犯下的错误，下次可以避免 | 写入 progress.md 的 Blockers/Risks |
| **新发现** | 本次发现的新模式、新约定、新最佳实践 | 写入 .omx/memory.md |

每个提取的模式的格式：
```
[类型] 标题
  场景：在什么情况下发现
  方法/教训：具体是什么
  复现条件：满足什么条件时可以使用/避免
  置信度：confirmed / uncertain
```

### 第 3 步：知识沉淀

将提取的模式写入对应位置：

1. **可复用方法** → 评估是否需要创建新技能。如果需要，调用 `$skillify`
2. **经验教训** → 追加到 `harness/progress.md` 的 Blockers/Risks 表格末尾
3. **新发现** → 追加到 `.omx/memory.md` 的对应分区（架构/规范/决策等）

### 第 4 步：完成声明

输出复盘摘要：

```markdown
## 会话复盘摘要

**会话时长**：[起止时间]
**文件变更**：N 个创建 + M 个修改 + K 个删除
**检查通过率**：X/Y (其中 A 个 CRITICAL 通过)
**提取的模式**：
  - 可复用方法：N 个（其中 X 个可转化为技能）
  - 经验教训：M 个
  - 新发现：K 个

**建议创建技能**：[列出值得技能化的方法名]
**下次会话启动建议**：[基于本次复盘的建议]
```

---

## 模式提取的优先级判断

| 条件 | 优先级 | 说明 |
|------|--------|------|
| 本次会话中重复使用了 3 次以上的方法 | P0 | 立即 skillify |
| 本次会话中发现的错误导致 > 30 分钟返工 | P1 | 必须记录经验教训 |
| 本次会话中发现的新模式未在任何文档中 | P1 | 必须写入 memory.md |
| 本次会话中使用了新工具/新 API | P2 | 记录使用方法 |
| 本次会话中优化了已有流程 | P2 | 更新已有技能 |

---

## 反模式

| 反模式 | 说明 | 纠正 |
|--------|------|------|
| 跳过复盘直接关闭会话 | FATAL | 至少执行第 1 步（事实回顾） |
| 只总结"做了什么"不提取模式 | ERROR | 复盘的核心产出是模式，不是工作总结 |
| 提取的模式过于笼统 | WARNING | 必须有"复现条件"才能复用 |
| 不写入持久化文件 | FATAL | 模式提取必须写入文件，不能只存在于对话中 |
| 提取的模式无置信度标注 | WARNING | uncertain 的模式需要额外验证 |

---

## 与其他技能的关系

```
session-retro → skillify（模式转化为技能）
session-retro → writing-skills（技能编写）
session-retro → .omx/memory.md（知识沉淀）
session-retro → progress.md（经验教训记录）
```

`sesssion-retro` 是持续学习（Continuous Learning）闭环的触发者——它将零散的经验转化为结构化的知识。

---

## 成功标准

- 至少提取 1 个可复用模式
- 至少记录 1 条经验教训
- .omx/memory.md 已更新
- progress.md 的 Blockers/Risks 已同步
- 复盘摘要已输出
