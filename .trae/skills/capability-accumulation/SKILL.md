# Capability Accumulation — 能力累计框架
## 定位
本技能是一个**个人成长操作系统**，将 Hermes Agent 的六种核心能力累积模式转化为人类可执行的成长框架。它是一个**闭环增长引擎**——每次经历都被捕获、技能化、联网、度量，最终形成自我增强的能力飞轮。
## 设计哲学：来自 Hermes Agent 的六种模式
| Hermes 模式 | 人类对应 | 核心机制 |
|------------|---------|---------|
| **闭环学习** | 经验→技能→改进→再经验 | 技能从经验中自动创建，使用中自我改进 |
| **技能系统** | 方法论/框架/清单的渐进积累 | 渐进式披露 + 定期策展 (7日循环) |
| **记忆系统** | 有界知识库 + 全量历史搜索 | MEMORY.md(核心) + FTS5(全量搜索) |
| **个性化** | 用户画像 + 上下文文件 | SOUL.md + AGENTS.md + USER.md |
| **度量可视化** | 能力雷达图 + 里程碑追踪 | 使用统计 + LLM 摘要分析 |
| **自动化** | 定期复盘 + 委派式成长 | 定时任务 + 子任务委派 |

## 触发条件
- 完成一个非平凡任务后（≥3 个步骤或遇到 ≥1 个非预期问题）
- 会话/项目阶段结束时
- 发现可复用的新方法或模式时
- 用户要求进行"能力复盘"、"经验沉淀"、"成长总结"时
- 定期（建议每周）的 Curator 策展循环
## 工作流入口
| 场景 | 入口 | 说明 |
|------|------|------|
| 刚完成任务 | `$aar` — 事后复盘 | 结构化的 After-Action Review |
| 做了关键决策 | `$decision-log` — 决策记录 | 记录决策背景、选项、理由 |
| 有了灵感/发现 | `$insight` — 洞察捕获 | 快速记录"aha moment" |
| 定期策展 | `$curator` — 能力策展 | 7 天周期的技能审查、合并、裁剪 |
| 成长总览 | `$growth-radar` — 能力雷达 | 多维度能力可视化评估 |

## 第 1 层：经验捕获
### 事后复盘 (AAR) — 核心四问
1. **预期是什么？** — 任务开始时的期望和计划
2. **实际发生了什么？** — 客观事实，不做评价
3. **为什么有差异？** — 根因分析，区分可控/不可控因素
4. **下次怎么做？** — 具体的、可执行的改进措施
### 决策日志 (Decision Log)
记录架构决策和技术选型：背景和约束条件、备选方案（≥2 个）、选择理由和权衡、预期后果和验证方式。
### 洞察日记 (Insight Journal)
快速捕获灵感和发现："原来如此！"时刻、新发现的最佳实践、识别出的反模式、跨领域类比。
### 错误手册 (Error Manual)
记录犯错经历：错误描述和上下文、根因分类（知识盲区/粗心/系统限制/沟通问题）、预防措施、检测信号。

## 第 2 层：能力技能化
### 技能创建触发器
| 触发器 | 说明 |
|--------|------|
| **复杂度阈值** | 任务涉及 ≥5 个步骤且可复用 |
| **纠错路径** | 从错误中找到正确方法后 |
| **用户纠正** | 被纠正后提炼正确方法 |
| **重复使用** | 同一方法在 ≥3 个场景中使用 |
### 渐进式披露 (Progressive Disclosure)
```
Level 0: 能力清单 → [{名称, 领域, 等级}, ...]  — 概览
Level 1: 能力卡片 → 完整的方法论 + 示例 + 注意事项
Level 2: 深度参考 → 相关决策、复盘、源码引用
```
### Curator 策展循环（建议 7 天）
1. **审查 (Review)**：评估每项能力的当前价值和准确性
2. **分级 (Grade)**：按使用频率、成功率、通用性打分
3. **合并 (Consolidate)**：合并重叠或相似的能力
4. **裁剪 (Prune)**：移除过时或低价值的能力
5. **升级 (Level Up)**：标记需要深化的能力

## 第 3 层：知识网络
### 有界记忆 + 全量搜索
| 层级 | 对应 | 容量 | 用途 |
|------|------|------|------|
| **核心记忆** | MEMORY.md (2,200 字符) | 有限 | 始终在上下文的关键事实 |
| **全量历史** | FTS5 会话搜索 | 无限 | 需要时搜索的历史记录 |
### 知识链接
能力之间建立显式关联：**前置依赖**（学习 B 前需要掌握 A）、**互补关系**（X 和 Y 结合使用效果更好）、**替代关系**（Z 是 W 的轻量替代）。

## 第 4 层：成长度量
### 能力雷达图（六维度）
```text
        技术深度
           ▲
          /|\
         / | \
工程思维 ├──┼──┤ 领域知识
         \ | /
          \|/
    软技能 ──┼── 系统设计
          /|\
         / | \
        学习力  │  领导力
              ▼
```
每个维度 1-5 分自评，每月更新一次。
### 投入产出追踪
| 追踪维度 | 数据源 | 分析频率 |
|----------|--------|----------|
| 学习时间分布 | 时间日志 | 每周 |
| 能力成长速度 | 能力卡片更新 | 每月 |
| 问题解决效率 | 复盘数据 | 每任务 |
| 新技能获取率 | 技能创建记录 | 每月 |

## 第 5 层：自动化与委派
| 周期 | 活动 | 描述 |
|------|------|------|
| **每日** | 洞察捕获 | 记录当天的 "aha moment" 和错误 |
| **每任务** | 事后复盘 | 完成非平凡任务后执行 AAR |
| **每周** | Curator 策展 | 审查、分级、合并、裁剪能力 |
| **每月** | 能力雷达更新 | 更新六维度自评分数 |
| **每季度** | 里程碑回顾 | 检查季度目标完成情况 |

## 第 6 层：生态连接
维护结构化的知识来源清单：
- **一手来源**（官方文档、源码）— 关注领域、更新频率
- **二手来源**（博客、教程）— 质量评级、关注主题
- **社区来源**（论坛、讨论组）— 活跃度、主要话题
- **人际来源**（导师、同行）— 领域、互动频率、最近交流日期

## 反模式
1. **过度记录** — 不是每件事都需要复盘。遵循触发器标准，而非机械执行。
2. **完美主义** — 能力卡片不需要完美。采用渐进改进模式，先粗糙地记录，再在使用中打磨。
3. **孤立积累** — 能力之间应该建立链接，形成网络而非孤岛。
4. **被动的成长** — 框架是工具，真正的成长需要主动应用和反思。
5. **一次性冲刺** — 能力积累是马拉松，每周 15 分钟策展比每季度 3 小时冲刺更有效。
