# CCG — Claude-Codex-Gemini 三模型协作编排

## 定位

将复杂任务分解后，并行分派给三个模型分别处理——Claude 负责综合与分析、Codex 负责架构与安全、Gemini 负责 UI 与文档——最终由 Claude 综合三方输出形成统一结论。适用于需要多模型视角的审查、分析或设计任务。

## 触发条件

- 用户提到 `ccg`、`tri-model`、`claude codex gemini`
- 需要后端分析 + 前端/UI 同时处理
- 需要多视角代码审查（架构 + 设计/UX）
- 需要交叉验证（Codex 和 Gemini 可能不同意见）
- 需要快速的多顾问并行输入

## 模型分工

| 模型 | 主要职责 | 适用场景 |
|------|---------|---------|
| **Claude** | 综合协调、最终综合、逻辑分析 | 任务分解、冲突调和、最终报告 |
| **Codex** | 架构审查、安全性、后端逻辑 | 代码正确性、架构风险、测试策略 |
| **Gemini** | UI/UX 设计、文档质量、可读性 | 用户体验、内容清晰度、边界用例 |

## 执行流程

### 第 1 步：分解任务

将用户请求拆分为两个顾问提示：

- **Codex 提示**：聚焦架构、正确性、后端、风险、测试策略
- **Gemini 提示**：聚焦 UI/内容清晰度、替代方案、边界可用性、文档打磨
- **综合计划**：如何调和冲突

### 第 2 步：并行调用

同时向两个模型发起请求，各自独立工作。

### 第 3 步：收集输出

收集两个模型的输出结果，记录：
- 各自的关键发现
- 一致的建议
- 冲突的观点
- 各自的置信度

### 第 4 步：Claude 综合

Claude 负责综合三方视角，输出统一的最终答案：

1. **一致建议**：两方都认可的建议——直接采纳
2. **冲突建议**：两方意见不一致——显式列出，给出 Claude 的判断和理由
3. **最终方向**：选择推荐的方向 + 理由
4. **行动清单**：具体的后续行动步骤

## 降级策略

| 情况 | 策略 |
|------|------|
| 一个模型不可用 | 使用可用模型 + Claude 综合，明确标注缺失视角和风险 |
| 两个模型都不可用 | 降级为 Claude 独立回答，声明 CCG 外部顾问不可用 |
| 某一方结果质量低 | 标注低质量结果，Claude 侧重另一方，必要时自行补充 |

## 反模式 / 红牌

| 反模式 | 说明 |
|--------|------|
| 不分解直接让模型做同一件事 | 红牌。必须按分工拆解为不同角度的提示 |
| 跳过冲突调和 | 红牌。必须显式列出冲突并给出判断 |
| 一方不可用不降级 | 红牌。必须降级并标注风险 |
| 任务不适合多模型 | 黄牌。简单查询不需要三模型协作 |
| 综合时偏袒某一方 | 黄牌。Claude 必须中立判断 |
| 不生成行动清单 | 黄牌。综合后必须有可执行下一步 |

## 成功标准

- 两个模型都收到了按分工定制的提示
- 两方的输出已收集并对比
- 一致建议已合并
- 冲突建议已显式列出并由 Claude 给出判断
- 生成了统一的综合报告
- 报告中包含可执行的行动清单
