# OMC Conversation Continuity — 会话连续性

Clean-room OMX 会话连续性技能，仅受 OMC (Oh My Conversation) 高层概念启发。本技能不复制 OMC 的实现、提示词、措辞、控制流或运行时代码。在此仓库的 MIT 许可技能约定下重新实现这一理念。

Credit: 受 OMC 会话连续性概念启发，从概念重新实现，遵循 MIT 许可。

## 定位

**HARD-GATE**：当上下文窗口使用率超过 70%，或用户要求开启新会话/生成手交提示词时，必须加载本技能。

本技能确保 AI 工程工作区中的会话状态可被压缩、序列化、并在新会话中可靠恢复，避免因上下文窗口溢出导致的工作丢失。

## 触发条件

- 用户要求"开启新会话"、"重新开始"、"压缩上下文"
- 上下文窗口使用率接近上限（≥70%），需要主动手交
- 长期项目需要在多个会话中持续推进
- 对话过长，需要生成手交提示词以便在新会话中继续
- 跨会话避免重复工作
- 会话结束时需要留下结构化的手交信息

## 不触发条件

- 上下文窗口使用率 < 50% 且用户未主动请求 → 不主动手交
- 任务可在当前会话完成 → 正常执行，不需要此技能
- 用户要求的是 Git worktree 隔离 → 使用 `$using-git-worktrees`
- 仅需更新进度日志 → 更新 `harness/progress.md` 即可

## 核心原则

1. **最小充分手交**：只压缩必要信息，不丢失关键上下文
2. **结构化优先**：手交输出遵循固定模板，确保可解析
3. **证据保留**：关键决策和验证结果必须保留，不可丢弃
4. **无歧义续接**：接手代理可以从手交信息独立理解当前状态
5. **渐进式压缩**：先尝试轻量压缩，不够再深入

## 上下文压缩策略

### 压缩等级

| 等级 | 触发条件 | 策略 |
|------|----------|------|
| **L0 — 无压缩** | 使用率 < 50% | 正常对话，不干预 |
| **L1 — 摘要** | 使用率 50-70% | 用摘要替换重复/冗余内容 |
| **L2 — 手交** | 使用率 70-85% | 生成结构化手交提示词，开启新会话 |
| **L3 — 深度手交** | 使用率 85%+ | L2 + 子任务拆分 + 状态文件同步 |

### L1 摘要策略

1. 识别可摘要的冗余内容（重复讨论、已解决的歧义、中间步骤）
2. 用一句话摘要替换冗余块
3. 保留所有：决策记录、验证证据、未解决问题、关键文件路径
4. 摘要后标记 `[已压缩: 原始内容略]`

### L2 手交策略

1. 执行完整手交提示词生成（见下方模板）
2. 将所有状态文件更新到最新
3. 建议用户开启新会话，粘贴手交提示词
4. 当前会话进入"只读手交模式"——不再执行新任务

### L3 深度手交策略

1. 执行 L2 所有步骤
2. 将未完成任务拆分为独立子任务
3. 为每个子任务生成独立手交提示词
4. 更新 `harness/feature_list.json` 标记当前进度
5. 附加 `harness/session-handoff.md` 深度上下文

## 手交提示词模板

```markdown
## SESSION HANDOFF — [日期时间]

### 项目状态
- **活跃目标**: [当前正在进行的 ultragoal/task]
- **进度百分比**: [估算]
- **最后完成的任务**: [具体描述 + 验证证据]
- **当前阻塞项**: [如有]

### 关键上下文
- **技术栈**: [语言、框架、关键依赖]
- **当前分支**: [git 分支名]
- **修改中的文件**: [文件列表 + 每文件的修改意图]
- **关键决策**: [已做出的重要决策及理由]

### 下一步任务
1. [下一步 1 — 具体可执行]
2. [下一步 2]
3. ...

### 注意事项
- [容易踩坑的点]
- [已知的限制或边界]
- [需要用户确认的事项]

### 参考文件
- `harness/progress.md` — 完整进度日志
- `harness/session-handoff.md` — 深度上下文
- `harness/feature_list.json` — 功能状态追踪

### 验证状态
- [上次验证命令 + 结果摘要]
- [未验证的风险]
```

## 执行流程

### 第 1 步：评估压缩需求

- 估算当前上下文窗口使用率
- 判断需要的压缩等级（L1/L2/L3）
- 确认用户意图：主动手交 vs 被动压缩

### 第 2 步：收集会话状态

- 回顾对话历史，提取关键信息：
  - 任务目标和验收标准
  - 已完成的步骤和验证结果
  - 当前进行中的任务
  - 已做出的决策和理由
  - 未解决的歧义和阻塞项
- 读取状态文件获取持久化状态：
  - `harness/progress.md`
  - `harness/session-handoff.md`
  - `harness/feature_list.json`

### 第 3 步：同步状态文件

- 将对话中的新进展写回 `harness/progress.md`
- 更新 `harness/session-handoff.md` 为当前完整上下文
- 更新 `harness/feature_list.json` 中的任务状态

### 第 4 步：生成手交提示词

- 按模板填充所有字段
- 确保下一步任务是**具体可执行的**，而非模糊描述
- 标注所有需要用户确认或注意的事项

### 第 5 步：验证手交完整性

执行自检：

- [ ] 手交提示词中包含活跃目标名称
- [ ] 下一步任务可被独立理解和执行
- [ ] 关键文件路径使用绝对路径
- [ ] 验证证据包含具体命令和结果
- [ ] 阻塞项有明确的解除条件
- [ ] 所有状态文件已同步到最新
- [ ] 手交提示词不超过合理长度（建议 2000 字内）

### 第 6 步：输出手交

- 将手交提示词完整呈现给用户
- 明确告知用户：复制此手交提示词到新会话即可续接
- 当前会话进入"手交模式"，不再接受新任务
- 如为 L3 深度手交，同时输出子任务手交包

## 恢复协议（新会话侧）

代理在新会话中接收到手交提示词后的恢复流程：

1. **解析手交**：提取活跃目标、当前分支、修改中的文件
2. **检查环境**：确认 git 分支、文件状态与手交一致
3. **读取状态文件**：加载 `harness/progress.md` 和 `harness/feature_list.json`
4. **验证上下文**：快速扫描修改中的文件，确认理解一致
5. **执行下一步**：按手交中的下一步任务开始工作
6. **更新进度**：完成第一个子任务后立即更新状态文件

## 与 OMX 系统的集成

| 集成点 | 触发时机 | 操作 |
|--------|----------|------|
| `harness/progress.md` | L2/L3 手交时 | 追加最新进度条目 |
| `harness/session-handoff.md` | L2/L3 手交时 | 完整覆盖为当前状态 |
| `harness/feature_list.json` | L3 深度手交时 | 更新活跃任务状态 |
| `.omx/memory.md` | 每次手交时 | 写入 NOTE：手交时间 + 压缩等级 |
| `.omx/notepad.md` | L3 深度手交时 | 更新 PRIORITY 区 |

## 与其他技能的协作

| 技能 | 关系 |
|------|------|
| `$token-budget` | 手交前可先尝试 Token 预算优化 |
| `$caveman-token-compress` | L1 压缩时使用极限压缩协议 |
| `$ultragoal` | 手交中保留 ultragoal 目标和进度 |
| `$using-git-worktrees` | 多任务并行时用 worktree 隔离代替手交 |
| `$session-retro` | 手交前可先做会话复盘，提取经验 |

## 反模式 / 红牌

| 反模式 | 严重性 | 说明 |
|--------|--------|------|
| 上下文溢出再手交 | **FATAL** | 使用率 ≥70% 时必须主动手交，不等溢出 |
| 手交缺少下一步 | **FATAL** | 手交必须包含具体可执行的下一步 |
| 手交信息模糊 | **FATAL** | "继续开发" 等模糊描述不可接受 |
| 丢失决策记录 | **FATAL** | 对话中做出的决策必须全部保留 |
| 不更新状态文件 | **FATAL** | 手交前必须同步所有状态文件 |
| 手交后继续执行 | **FATAL** | L2/L3 手交后当前会话不再执行新任务 |
| 手交过长 | **WARNING** | 手交提示词应精炼，≤2000 字 |
| 频繁手交 | **WARNING** | L2 手交至少间隔 10 个有效操作 |

## 输出物

1. **手交提示词**：结构化的会话续接提示词
2. **更新后的状态文件**：`harness/` 下所有相关文件已同步
3. **压缩摘要**（L1）：对话中冗余内容的摘要替换
4. **子任务手交包**（L3）：拆分后的独立任务手交

## 成功标准

- 接手代理仅凭手交提示词即可独立开始工作
- 所有关键决策和验证证据被保留
- 状态文件与手交内容一致
- 下一步任务具体、可执行、有明确完成标准
- 用户无需重复解释上下文
