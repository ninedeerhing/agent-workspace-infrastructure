# Curator 策展检查清单

## 概述

Curator 是能力累积框架的定期维护机制，借鉴 Hermes Agent v0.12+ 的 Curator 系统设计。建议每 7 天执行一次完整的策展循环，每次约 15-30 分钟。

## 策展循环（五步法）

### 第 1 步：审查 (Review)

**目标**：了解当前能力库的状态

- [ ] 查看 `capabilities.json`，确认能力总数和分布
- [ ] 按 `最近使用` 排序，识别最近活跃和长期未用的能力
- [ ] 按 `健康度` 筛选，关注"需更新"和"待归档"的能力
- [ ] 审核最近 30 天的新建能力，确认质量
- [ ] 检查是否有 `验证状态 = 未验证` 超过 30 天的洞察

### 第 2 步：分级 (Grade)

**目标**：客观评估每项能力的当前水平

- [ ] 为过去 30 天使用过的能力更新 `最近使用` 和 `使用次数`
- [ ] 评估是否有能力应该升降级（L1→L2, L2→L3 等）
- [ ] 对每项能力评定健康度：
  - **活跃**：过去 30 天使用过，方法有效
  - **稳定**：虽然最近没用，但方法仍然正确
  - **需更新**：方法有误或过时，需要修改
  - **待归档**：不再适用，可以移除

### 第 3 步：合并 (Consolidate)

**目标**：消除冗余，建立连接

- [ ] 检查能力之间是否存在内容重叠
- [ ] 可以合并的：选择一个主能力，将其他作为补充合并进去
- [ ] 不能合并但相关的：在"相关能力"字段建立链接
- [ ] 检查是否有"知识孤岛"（无任何链接的能力）
- [ ] 为孤岛能力补充链接

### 第 4 步：裁剪 (Prune)

**目标**：保持能力库的精简和高质量

- [ ] 归档超过 90 天未使用且健康度为"待归档"的能力
- [ ] 删除已被替代的决策记录（在决策日志中标记为"已替代"）
- [ ] 清理验证状态为"已证伪"的洞察
- [ ] 合并内容高度重复的复盘记录
- [ ] 将不常用但仍有价值的能力设置为"休眠"（保留但不显示在概览列表中）

### 第 5 步：升级 (Level Up)

**目标**：规划下一阶段的成长重点

- [ ] 选择 1-3 项能力作为未来 30 天的深化重点
- [ ] 为每项重点能力制定升级计划（如：L2 → L3）
- [ ] 检查能力雷达图，识别最需要提升的维度
- [ ] 更新学习地图，调整路径规划
- [ ] 如有必要，更新季度里程碑

## 策展节奏建议

| 活动 | 频率 | 预计时间 |
|------|------|----------|
| 快速浏览（审查第 1 步） | 每天 | 2 分钟 |
| 轻量策展（审查 + 裁剪） | 每周 | 10 分钟 |
| 完整策展（五个步骤） | 每两周 | 25 分钟 |
| 深度策展（含能力升级规划） | 每月 | 40 分钟 |

## 策展触发条件

除了定期执行，以下情况也应触发策展：

- 能力总数超过 30 项（认知过载阈值）
- 多个能力（≥3）标记为"需更新"
- 季度里程碑审查日期到达
- 完成重大项目或角色变化后
- 发现能力之间存在明显矛盾
