# Capability Accumulation — 能力累计框架

## 定位

本技能是一个**个人成长操作系统**，将 Hermes Agent 的六种核心能力累积模式转化为人类可执行的成长框架。它不是一个"学习清单"，而是一个**闭环增长引擎**——每次经历都被捕获、技能化、联网、度量，最终形成自我增强的能力飞轮。

## 设计哲学：来自 Hermes Agent 的六种模式

| Hermes 模式 | 人类对应 | 核心机制 |
|------------|---------|---------|
| **闭环学习** (Learning Loop) | 经验→技能→改进→再经验 | 技能从经验中自动创建，使用中自我改进 |
| **技能系统** (Skills System) | 方法论/框架/清单的渐进积累 | 渐进式披露 + 定期策展 (Curator 7日循环) |
| **记忆系统** (Memory System) | 有界知识库 + 全量历史搜索 | MEMORY.md(核心) + FTS5(全量搜索) |
| **个性化** (Personalization) | 用户画像 + 上下文文件 | SOUL.md + AGENTS.md + USER.md |
| **度量可视化** (Insights) | 能力雷达图 + 里程碑追踪 | 使用统计 + LLM 摘要分析 |
| **自动化** (Cron + Subagents) | 定期复盘 + 委派式成长 | 定时任务 + 子任务委派 |

## 触发条件

- 完成一个非平凡任务后（≥3 个步骤或遇到 ≥1 个非预期问题）
- 会话/项目阶段结束时
- 发现可复用的新方法或模式时
- 用户要求进行"能力复盘"、"经验沉淀"、"成长总结"时
- 定期（建议每周）的 Curator 策展循环

## 工作流入口

根据场景选择合适的入口：

| 场景 | 入口 | 说明 |
|------|------|------|
| 刚完成任务 | `$aar` — 事后复盘 | 结构化的 After-Action Review |
| 做了关键决策 | `$decision-log` — 决策记录 | 记录决策背景、选项、理由 |
| 有了灵感/发现 | `$insight` — 洞察捕获 | 快速记录"aha moment" |
| 定期策展 | `$curator` — 能力策展 | 7 天周期的技能审查、合并、裁剪 |
| 成长总览 | `$growth-radar` — 能力雷达 | 多维度能力可视化评估 |
| 技能化 | [skillify](skillify) | 将经验沉淀为可复用技能 |

## 第 1 层：经验捕获

### 1.1 事后复盘 (After-Action Review)

每次完成非平凡任务后执行。格式参考 `templates/aar.md`。

**核心四问**：
1. **预期是什么？** — 任务开始时的期望和计划
2. **实际发生了什么？** — 客观事实，不做评价
3. **为什么有差异？** — 根因分析，区分可控/不可控因素
4. **下次怎么做？** — 具体的、可执行的改进措施

**触发标准**：
- 完成 ≥5 个工具调用的任务
- 遇到错误或死胡同后找到了正确路径
- 用户纠正了你的方法
- 发现了非平凡的工作流

### 1.2 决策日志 (Decision Log)

记录架构决策和技术选型的结构化日志。格式参考 `templates/decision-log.md`。

**记录内容**：
- 决策背景和约束条件
- 考虑的备选方案（至少 2 个）
- 选择理由和权衡
- 预期后果和验证方式

### 1.3 洞察日记 (Insight Journal)

快速捕获灵感和发现的轻量级日志。格式参考 `templates/insight-journal.md`。

**触发条件**：
- "原来如此！" 时刻
- 发现新的最佳实践
- 识别出反模式
- 跨领域类比发现

### 1.4 错误手册 (Error Manual)

记录犯错经历的结构化"错题本"。每条记录包含：
- 错误描述和上下文
- 根因分类（知识盲区/粗心/系统限制/沟通问题）
- 预防措施
- 检测信号（下次如何提前发现）

## 第 2 层：能力技能化

### 2.1 技能创建触发器

借鉴 Hermes Agent 的 `skill_manage` 工具逻辑，以下情况触发能力技能化：

| 触发器 | 说明 |
|--------|------|
| **复杂度阈值** | 任务涉及 ≥5 个步骤且可复用 |
| **纠错路径** | 从错误中找到正确方法后 |
| **用户纠正** | 被纠正后提炼正确方法 |
| **重复使用** | 同一方法在 ≥3 个场景中使用 |

### 2.2 渐进式披露 (Progressive Disclosure)

能力卡片采用三级加载，节省认知负担：

```
Level 0: 能力清单 → [{名称, 领域, 等级}, ...]  — 概览
Level 1: 能力卡片 → 完整的方法论 + 示例 + 注意事项
Level 2: 深度参考 → 相关决策、复盘、源码引用
```

### 2.3 Curator 策展循环

借鉴 Hermes v0.12+ 的 Curator 系统，定期（建议 7 天）执行：

1. **审查 (Review)**：评估每项能力的当前价值和准确性
2. **分级 (Grade)**：按使用频率、成功率、通用性打分
3. **合并 (Consolidate)**：合并重叠或相似的能力
4. **裁剪 (Prune)**：移除过时或低价值的能力
5. **升级 (Level Up)**：标记需要深化的能力

策展检查清单：
- [ ] 过去 30 天使用了哪些能力？
- [ ] 哪些能力需要更新/修正？
- [ ] 哪些能力可以合并？
- [ ] 哪些新能力值得创建？
- [ ] 哪些能力已经过时可以归档？

### 2.4 能力卡片格式

```markdown
# [能力名称]

- **领域**: [技术领域]
- **等级**: [L1 了解 / L2 应用 / L3 掌握 / L4 传授]
- **创建日期**: [YYYY-MM-DD]
- **最近使用**: [YYYY-MM-DD]
- **来源**: [任务/项目/复盘 ID]

## 适用场景
[何时使用此能力]

## 方法步骤
1. [步骤一]
2. [步骤二]

## 关键洞察
- [核心要点]

## 常见陷阱
- [陷阱及避免方式]

## 相关能力
- [能力名称]: [关系说明]
```

## 第 3 层：知识网络

### 3.1 有界记忆 + 全量搜索

借鉴 Hermes 的双层记忆架构：

| 层级 | 对应 | 容量 | 用途 |
|------|------|------|------|
| **核心记忆** | MEMORY.md (2,200 字符) | 有限 | 始终在上下文的关��事实 |
| **全量历史** | FTS5 会话搜索 | 无限 | 需要时搜索的历史记录 |

**实践**：
- 核心记忆只保留最高频、最关键的知识点
- 80% 容量以上时必须合并/裁减
- 全量历史通过标签和时间戳索引

### 3.2 知识链接

能力之间建立显式关联：
- **前置依赖**："学习 B 前需要掌握 A"
- **互补关系**："X 和 Y 结合使用效果更好"
- **替代关系**："Z 是 W 的轻量替代"

### 3.3 定期策展

每周 Curator 循环中执行：
1. 识别知识孤岛（无链接的能力）
2. 发现知识集群（密集链接的能力群）
3. 补充跨领域链接
4. 将核心记忆同步到全量历史索引

## 第 4 层：成长度量

### 4.1 能力雷达图

六个维度评估当前能力状态：

```text
        技术深度
           ▲
          /|\
         / | \
工程思维 ├──┼──┤ 领域知识
         \ | /
          \|/
    软技能 ──┼── 系统设计
          /|\
         / | \
        学习力  │  领导力
              ▼
```

每个维度 1-5 分自评，每月更新一次。

### 4.2 里程碑地图

按季度划分的成长里程碑：

```markdown
## Q2 2026 里程碑

### 技术深度：L3 → L4
- [ ] 深入理解 XXX 源码
- [ ] 发表一篇技术分享
- [ ] 解决一个复杂生产问题

### 领域知识：L2 → L3
- [ ] 阅读 3 篇领域论文
- [ ] 完成领域认证
```

### 4.3 投入产出追踪

| 追踪维度 | 数据源 | 分析频率 |
|----------|--------|----------|
| 学习时间分布 | 时间日志 | 每周 |
| 能力成长速度 | 能力卡片更新 | 每月 |
| 问题解决效率 | 复盘数据 | 每任务 |
| 新技能获取率 | 技能创建记录 | 每月 |

## 第 5 层：自动化与委派

### 5.1 定期复盘日程

借鉴 Hermes 的 Cron 系统：

| 周期 | 活动 | 描述 |
|------|------|------|
| **每日** | 洞察捕获 | 记录当天的 "aha moment" 和错误 |
| **每任务** | 事后复盘 | 完成非平凡任务后执行 AAR |
| **每周** | Curator 策展 | 审查、分级、合并、裁剪能力 |
| **每月** | 能力雷达更新 | 更新六维度自评分数 |
| **每季度** | 里程碑回顾 | 检查季度目标完成情况 |

### 5.2 成长委派

将成长活动委派给工具或代理：

| 活动 | 委派方式 |
|------|----------|
| 错误模式分析 | 让 AI 分析最近的复盘记录，识别重复错误模式 |
| 能力缺口识别 | 对照目标职位/角色要求，识别能力差距 |
| 学习资源推荐 | 基于能力缺口，推荐最优学习资源 |
| 进度报告生成 | 自动汇总一段时间内的成长数据 |

## Curator 策展命令参考

```text
$curator review    — 审查所有能力卡片，标记过时/需更新项
$curator grade     — 为每项能力评定当前等级和健康度
$curator merge     — 合并重叠/相似能力
$curator prune     — 归档或删除低价值能力
$curator full      — 完整策展循环（review → grade → merge → prune）

$milestones        — 查看/更新季度里程碑
$leaning-map       — 生成学习地图
```

## 反模式

1. **过度记录** — 不是每件事都需要复盘。遵循触发器标准，而非机械执行。
2. **完美主义** — 能力卡片不需要完美。采用渐进改进模式，先粗糙地记录，再在使用中打磨。
3. **孤立积累** — 能力之间应该建立链接，形成网络而非孤岛。
4. **被动的成长** — 框架是工具，真正的成长需要主动应用和反思。
5. **一次性冲刺** — 能力积累是马拉松，每周 15 分钟策展比每季度 3 小时冲刺更有效。
