# Skillify — 技能提取元技能

## 定位

元技能——从当前会话的交互轨迹中识别可复用的工作流模式，并将其提炼为结构化的 SKILL.md 文件。避免每次都重新发现相同的工作方法。

## 触发条件

- 用户提到 `skillify`、`extract skill`、`create skill from session`
- 本次会话成功完成了一个有价值的、可复用的工作流
- 用户表示"把这次的方法记下来"、"沉淀为技能"
- 会话中存在值得编码为技能的决策启发式或约束条件

## 质量门槛

提取技能前，以下三条必须同时满足：

- ❌ "Google 5 分钟能查到吗？" → 不能。否则不值得提技能。
- ✅ "是否特定于这个代码库、项目或工作流？" → 是。
- ✅ "是否需要经过实打实的调试、设计或操作努力才发现？" → 是。

优先提取编码了决策启发式、约束条件、陷阱和验证步骤的技能。避免提取通用代码片段、模板代码或库用法示例——这些属于普通文档的范畴。

## 执行流程

### 第 1 步：回顾会话轨迹

- 梳理本次会话完成的关键任务
- 识别执行过程中的关键决策点
- 标记出现过的错误和纠正方式
- 记录哪些步骤被证明是必要且不可跳过的

### 第 2 步：识别可复用模式

从轨迹中提取可复用要素：

| 要素 | 说明 |
|------|------|
| **输入** | 技能开始时需要什么信息/上下文 |
| **有序步骤** | 经过验证的执行顺序 |
| **成功标准** | 如何判断技能执行成功 |
| **约束/陷阱** | 容易出错的地方和必须遵守的限制 |
| **验证证据** | 如何确认每一步的正确性 |
| **最佳存放位置** | 技能应放在哪里（项目级/用户级） |

### 第 3 步：判断存放形式

| 形式 | 说明 |
|------|------|
| 项目内建技能 | 放在项目 `skills/<name>/SKILL.md`，与团队共享 |
| 用户学习技能 | 放在用户级技能目录，个人使用 |
| 仅文档 | 不适合作为技能，但值得记录为文档 |

### 第 4 步：生成 SKILL.md

按照 `writing-skills` 元技能的结构规范生成技能文件。

**必须包含**：
- YAML frontmatter（`name` + `description`）
- description 遵循"描述陷阱"原则——只描述触发条件，不暴露工作流摘要
- 定位说明
- 触发条件
- 核心步骤/流程
- 反模式/红牌表
- 成功标准

**description 陷阱示例**：

❌ **错误**：
```yaml
description: 用于从会话中提取技能，包含5步检查和生成SKILL.md输出。
```
这暴露了工作流细节，AI 会跳过加载直接执行。

✅ **正确**：
```yaml
description: 当需要从当前会话中提取可复用的工作流模式并创建为技能文件时使用。
```
只描述"何时使用"，不描述"里面有什么"。

### 第 5 步：用户审查

- 将生成的 SKILL.md 草案呈现给用户
- 标注仍有模糊不确定的地方
- 收集用户反馈并修订
- 确认技能名称和存放位置

### 第 6 步：注册技能

- 将 SKILL.md 写入正确的技能目录
- 确保 frontmatter 有效
- 提醒用户：未提交的技能仅在当前 worktree 有效

## 技能文件规范

### 最小 Frontmatter

```yaml
---
name: <skill-name>
description: <仅含触发条件的单行描述>
---
```

### 正文结构

1. **定位**：一句话说明技能在流程中的位置
2. **触发条件**：何时加载这个技能
3. **核心原则**：3-5 条指导原则
4. **步骤/流程**：清晰的步骤分解
5. **反模式/红牌表**：禁止的行为和常见错误
6. **成功标准**：如何判断技能执行成功

## 反模式 / 红牌

| 反模式 | 说明 |
|--------|------|
| 提取 Google 能查到的内容 | 红牌。必须是经过实践发现的独特模式 |
| description 含工作流摘要 | 红牌。只应描述触发条件 |
| 没有 YAML frontmatter | 红牌。纯 Markdown 不是有效技能 |
| 步骤过于笼统 | 黄牌。步骤应具体可执行 |
| 不标注模糊点 | 黄牌。不确定处必须标注留给审查 |
| 提取一次性任务 | 黄牌。必须是可复用的工作流 |
| 缺少反模式表 | 黄牌。每个技能都应有反模式表 |

## 成功标准

- 提取的流程在类似场景下可复现
- SKILL.md 包含完整 YAML frontmatter
- description 仅含触发条件，不含工作流细节
- 步骤清晰可执行，不笼统
- 有反模式/红牌表
- 模糊不确定处已标注
- 用户已审查确认
