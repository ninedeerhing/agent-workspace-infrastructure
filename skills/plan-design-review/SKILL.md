# Plan Design Review — 设计审查

## 定位

以高级设计师视角审查产品设计。通过 7 个通道评估设计质量，每个通道 0-10 评分。

## 触发条件

- 有设计方案（线框图、原型、设计文档）
- 需要从 UX/UI 角度审查
- 准备进入实现阶段前

## 7 个审查通道

### 1. 清晰度（Clarity）

- 用户能立即理解界面吗？
- 信息层级是否清晰？
- 操作路径是否直观？
- 评分 0-10

### 2. 一致性（Consistency）

- 与设计系统一致吗？
- 交互模式是否统一？
- 视觉语言是否连贯？
- 评分 0-10

### 3. 效率（Efficiency）

- 核心任务需要多少步？
- 有快捷键或快捷操作吗？
- 重复操作是否优化？
- 评分 0-10

### 4. 容错性（Error Tolerance）

- 错误状态是否优雅处理？
- 有撤销机制吗？
- 危险操作有确认吗？
- 评分 0-10

### 5. 可访问性（Accessibility）

- 色盲用户能使用吗？
- 键盘导航是否完善？
- 屏幕阅读器友好吗？
- 评分 0-10

### 6. 反馈（Feedback）

- 每次操作有即时反馈吗？
- 加载状态是否可见？
- 成功/失败是否明确告知？
- 评分 0-10

### 7. 美观（Aesthetics）

- 视觉设计是否吸引人？
- 是否符合品牌调性？
- 排版和间距是否舒适？
- 评分 0-10

## 评估标准

| 总分 | 评估 |
|------|------|
| 60-70 | 优秀，可以进入实现 |
| 45-59 | 良好，有改进空间 |
| 30-44 | 需要重大改进 |
| < 30 | 需要重新设计 |

## 反模式 / 红牌

| 反模式 | 说明 |
|--------|------|
| 跳过可访问性审查 | 红牌。可访问性是基本要求 |
| 只评不留建议 | 黄牌。每个通道需有改进建议 |
| 凭感觉评分 | 黄牌。评分要有具体理由 |
| 忽略移动端 | 黄牌。响应式设计必须审查 |
