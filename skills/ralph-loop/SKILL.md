# Ralph Loop — 自引用持久循环

## 定位

一个自引用的持久执行循环。通过并行委派、强制架构验证和回归重验证机制，确保每次循环的质量和一致性。

## 触发条件

- 需要多轮迭代的长期任务
- 持续集成式开发
- 需要反复验证和完善
- 每次迭代都可能影响之前的决策

## 核心机制

### 并行委派

- 在循环中可以并行分派多个独立任务
- 每个任务由独立子代理执行
- 异步收集结果

### 强制架构验证

- 每次循环结束时，Architect 必须重新验证架构一致性
- 检查新修改是否引入架构退化
- 如果架构方向偏离，立即标记

### 回归重验证

- 每次循环结束时，运行完整回归测试
- 不仅是新修改的测试，而是全部测试
- 确保没有引入回归

## 循环结构

```
START
  ├→ 读取当前状态
  ├→ 选择本轮任务
  ├→ 并行委派执行
  ├→ 收集结果
  ├→ 架构验证
  ├→ 回归测试
  ├→ 记录进展
  └→ 判断是否继续 → 继续/结束
```

## 循环终止条件

- 所有目标满足成功标准
- 用户命令停止
- 达到预设的最大迭代次数
- 架构验证连续失败 2 次

## 反模式 / 红牌

| 反模式 | 说明 |
|--------|------|
| 跳过架构验证 | 红牌。每轮都必须验证架构 |
| 不运行回归 | 红牌。每轮必须运行回归测试 |
| 无限循环 | 红牌。必须有终止条件 |
| 并行任务有依赖 | 红牌。有依赖不能并行 |
| 不在循环外思考 | 黄牌。定期跳出循环检查大局 |
