# Subagent-Driven Development — 子代理驱动开发

## 定位

当拥有完整的实现计划和子代理执行环境时，使用多代理并行实现来加速开发。本技能编排子代理的分派、协调和审查。

## 触发条件

- `writing-plans` 已完成，有完整的实现计划
- 环境支持分派多个子代理
- 计划中的任务之间无或仅有少量共享状态依赖

## 核心流程

### 第 1 步：读取计划

- 完全理解 `writing-plans` 输出的实现计划
- 识别任务之间的依赖关系
- 标记可并行的任务和必须串行的任务

### 第 2 步：创建 TodoWrite

- 将计划中的每个步骤映射为 TodoWrite 条目
- 标记并行任务和串行任务的依赖关系

### 第 3 步：分派实现子代理

对于每个独立任务：
1. 创建子代理，给予明确指令（实现内容、文件路径、测试要求、完成标准）
2. 子代理独立执行 RED-GREEN-REFACTOR 循环
3. 子代理完成后返回状态报告

### 第 4 步：规范审查

每个子代理完成后，立即审查：是否符合设计规范、接口是否一致、有无超出范围修改。

### 第 5 步：代码质量审查

委托独立的 `requesting-code-review` 子代理执行代码审查。

### 第 6 步：审查循环

- 如有问题，返回给实现子代理修正
- 循环至多 3 次，超过则上报协调者

### 第 7 步：最终整体审查

- 所有独立任务完成后，执行一次整体审查
- 检查跨任务的接口一致性
- 运行完整的集成测试

### 第 8 步：过渡

- 通过所有审查 → 过渡到 `finishing-dev-branch`
- 有问题 → 回到对应步骤修正

## 四状态协议

每个子代理返回时必须使用以下四个状态之一：

| 状态 | 含义 | 后续动作 |
|------|------|----------|
| `DONE` | 任务完成，所有测试通过 | 进入审查 |
| `DONE_WITH_CONCERNS` | 完成但有不确定的问题 | 审查时重点关注 |
| `BLOCKED` | 遇到阻塞无法继续 | 协调者介入解决 |
| `NEEDS_CONTEXT` | 缺少上下文信息 | 补充上下文后重试 |

## 反模式 / 红牌

| 反模式 | 说明 |
|--------|------|
| 子代理范围过大 | 红牌。一个子代理只处理一个独立任务 |
| 子代理间共享状态 | 红牌。必须无共享状态 |
| 跳过审查 | 红牌。每个子代理输出必须审查 |
| 审查卡住 | 黄牌。审查循环最多 3 次后升级 |
| 忽略状态协议 | 红牌。每个子代理必须返回四状态之一 |
