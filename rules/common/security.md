# 安全规则 (Security Rules)

## 适用范围
所有代码文件和配置文件。任何提交前必须通过安全检查。

## ALWAYS — 必须遵守
1. **无硬编码密钥** — 所有密钥、Token、密码通过环境变量或密钥管理服务获取
2. **所有用户输入已验证** — 服务端验证所有输入（类型、长度、范围、格式）
3. **SQL注入防护** — 始终使用参数化查询或ORM，永不拼接SQL
4. **XSS防护** — 输出到HTML时必须清理，使用CSP头
5. **CSRF保护** — 所有状态变更请求必须验证CSRF Token
6. **认证/授权已验证** — 每个端点检查认证状态和权限
7. **速率限制** — 所有公开端点有速率限制
8. **错误消息不泄露敏感数据** — 生产环境不输出堆栈跟踪

## NEVER — 严禁
1. 不提交包含密钥的代码
2. 不使用弱加密算法（MD5, SHA1用于安全用途）
3. 不在日志中记录密码、Token、个人信息
4. 不信任客户端验证结果
5. 不在URL中传递敏感数据
6. 不使用eval()、exec()执行不可信输入

## 密钥管理规范
- 本地开发: .env文件（已加入.gitignore）
- CI/CD: 使用CI平台的Secrets功能
- 生产: 使用密钥管理服务

## 安全响应协议
1. 立即停止 → 不继续修改存在安全问题的代码
2. 使用security-reviewer代理 → 全面安全审查
3. 修复CRITICAL问题 → 最高优先级
4. 轮换暴露的密钥
5. 审查整个代码库

## 提交前安全检查清单
- [ ] 无硬编码密钥、Token、密码
- [ ] 无console.log包含敏感数据
- [ ] 所有用户输入已验证
- [ ] SQL查询使用参数化
- [ ] 无eval()或类似危险函数
- [ ] 错误消息不泄露实现细节
- [ ] 第三方依赖无已知高危漏洞
- [ ] 认证和授权逻辑已审查
