# 测试规则 (Testing Rules)

## 适用范围

所有功能代码。**NO PRODUCTION CODE WITHOUT A FAILING TEST FIRST**。

## ALWAYS — 必须遵守

1. **TDD 强制流程** — RED（写失败测试）→ GREEN（最小实现）→ REFACTOR（清理）
2. **先写测试** — 在实现代码之前先写好至少一个失败的测试
3. **AAA 结构** — Arrange → Act → Assert 三段式
4. **测试命名** — `test_[被测方法]_[场景]_[预期结果]`
5. **独立测试** — 每个测试独立运行，不依赖执行顺序
6. **覆盖率目标** — 行覆盖 ≥ 80%，分支覆盖 ≥ 70%
7. **边界测试** — 测试空值、边界、异常、并发场景
8. **回归测试** — 每个 Bug 修复必须伴随一个回归测试

## NEVER — 严禁

1. 不在没有失败测试的情况下写生产代码
2. 不跳过任何失败的测试
3. 不为通过测试而降低断言标准
4. 不测试实现细节（测试行为，不测试私有方法）
5. 不过度 Mock（Mock 外部依赖，不 Mock 被测对象内部）

## 测试分类

| 类型 | 目标 | 占比 |
|------|------|------|
| 单元测试 | 验证单个函数/方法 | 80%+ |
| 集成测试 | 验证模块间交互 | 15% |
| E2E测试 | 验证完整用户流程 | 5% |

## 必测场景

- 正常输入 → 正确输出
- 空值输入 → 适当处理
- 边界输入 → 边界正确
- 异常输入 → 优雅失败
