# 数据库设计规范

## 1. 迁移策略

- 每次数据库结构变更必须创建独立迁移文件，禁止手动修改生产库
- 迁移文件命名格式：`V<序号>__<描述>.sql`（如 `V001__create_users_table.sql`）
- 每个迁移文件必须包含 `up`（正向迁移）和 `down`（回滚迁移）
- 已部署到生产的迁移文件**禁止修改**——回退必须通过新的迁移文件实现
- 迁移文件按版本号顺序执行，跳号视为错误
- CI 中必须包含迁移检查步骤

## 2. 命名规范

| 对象     | 规范                    | 示例                          |
| -------- | ----------------------- | ----------------------------- |
| 表名     | snake_case，英文复数    | `users`、`order_items`        |
| 主键     | `id`（UUID 或 自增）    | `id UUID PRIMARY KEY`         |
| 外键     | `<表名单数>_id`         | `user_id`、`order_id`         |
| 时间戳   | `created_at`、`updated_at` | `created_at TIMESTAMPTZ`   |
| 布尔字段 | `is_<形容词>`           | `is_active`、`is_deleted`     |
| 索引     | `idx_<表名>_<列名>`     | `idx_users_email`             |
| 唯一约束 | `uq_<表名>_<列名>`      | `uq_users_email`              |

## 3. 索引设计

- WHERE 子句和 JOIN 条件的列必须建索引
- 高频查询优先创建**覆盖索引**（包含 SELECT 所有列，避免回表）
- 复合索引遵循**最左前缀原则**，区分度高的列放左侧
- 写密集型表每个表索引不超过 5 个
- 避免在低区分度列上建索引（如 `is_active`、`status` 枚举值 < 5 种）
- 定期执行 `EXPLAIN` 分析慢查询，验证索引有效性
- 禁止在生产环境直接创建索引——通过迁移文件执行，并在低峰期操作

## 4. 查询规范

- **禁止** SQL 拼接——所有查询必须使用参数化查询
- **禁止** `SELECT *`——必须显式列出所需列
- 批量操作使用批处理（每批 ≤ 1000 条），禁止逐条执行
- ORM 开启 N+1 查询检测日志，定期排查
- 复杂查询编写注释说明意图和预期结果集大小
- 查询结果集超过 1000 条必须分页

## 5. 备份与回滚

- 生产数据库必须配置自动全量备份（每日）和增量备份（每小时）
- 备份文件保留至少 30 天，异地存储至少一份
- 每次重大发布前必须执行数据库快照
- 回滚计划必须包含在发布文档中，并经过评审
- 定期（每季度）执行备份恢复演练

## 6. 安全规范

- 数据库密码存入密钥管理器，禁止出现在代码或配置文件原文中
- 应用连接数据库使用最小权限账户（按需分配 CRUD 权限）
- 敏感字段（密码哈希、手机号、身份证号）使用加密存储
- 生产库禁止从公网直接访问——仅允许通过跳板机或 VPN
