# 编码风格规则 (Coding Style Rules)

## 适用范围
所有源代码文件。

## ALWAYS — 必须遵守
1. **不可变性优先** — 优先使用 const、final、不可变数据结构
2. **单一职责** — 每个函数做好一件事；函数体不超过40行
3. **文件组织** — 一个文件一个主要导出类/模块；文件大小不超过300行
4. **错误处理** — 永远不吞掉异常；错误要么处理掉要么向上传播
5. **输入验证** — 所有公开API入口验证输入，尽早失败（Fail Fast）
6. **显式优于隐式** — 代码意图应清晰表达，避免魔法数字
7. **命名清晰** — 变量名描述"是什么"，函数名描述"做什么"
8. **嵌套控制** — 嵌套深度不超过4层
9. **无注释代码** — 提交前删除所有被注释掉的代码块
10. **匹配现有风格** — 修改已有代码时保持一致

## NEVER — 严禁
1. 不为未来需求写代码（YAGNI）
2. 不创建不必要的抽象层
3. 不做未请求的重构
4. 不修改与任务无关的代码
5. 不添加未请求的功能
6. 不使用any类型（TypeScript，除非有充分理由）
7. 不保留console.log/debugger语句
8. 不硬编码配置值

## 代码注释规则
- 函数和类必须有注释说明用途
- 复杂逻辑段落需要行内注释
- 注释说明"为什么"而非"是什么"
