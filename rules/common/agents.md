# 代理编排规则 (Agent Orchestration Rules)

## 代理清单
| 代理 | 用途 | 触发条件 |
|------|------|----------|
| orchestrator | 主编排 | 多代理复杂任务 |
| planner | 需求拆解 | 模糊需求到结构化计划 |
| architect | 系统设计 | 架构决策 |
| explorer | 代码库探索 | 不熟悉代码库时 |
| executor | 执行实现 | 有明确计划时 |
| code-reviewer | 代码审查 | 代码变更后 |
| security-reviewer | 安全审查 | 涉及安全/认证/密钥 |
| test-engineer | 测试设计 | 需要测试策略 |
| debugger | 系统调试 | Bug修复 |
| verifier | 完成验证 | 声称完成前 |

## ALWAYS — 必须遵守
1. **即时代理使用** — 复杂功能→planner，代码变更→code-reviewer，Bug→test-engineer，架构→architect
2. **并行执行** — 对独立操作使用并行Task执行
3. **技能优先** — 检查是否有匹配技能可用
4. **代理隔离** — 每个子代理只获得必要上下文
5. **结果综合** — 主编排器负责综合各子代理结果

## NEVER — 严禁
1. 不跳过code-reviewer直接合并
2. 不让单个代理处理超过其职责范围的任务
3. 不在子代理之间传递上下文
4. 不同时分派互相依赖的任务

## 多视角分析
- 事实审查员 — 验证代理输出的准确性
- 安全专家 — 检查安全影响
- 一致性审查员 — 检查与现有系统的兼容性
- 冗余检查员 — 发现重复代码和过度抽象
